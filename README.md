# sapar-skills — скиллы для AI-агентов

Маркетплейс из трёх плагинов:

| Плагин | Скиллы | Что делает |
|---|---|---|
| `mirea-moodle` | `mirea-moodle`, `syncshare-audit` | **online-edu.mirea.ru** (Moodle РТУ МИРЭА): вход через SSO с кодом 2FA, курсы, папки, скачивание методичек и датасетов, docx → pdf; read-only аудит покрытия тестов SyncShare для своего аккаунта |
| `job-search` | `job-digest`, `job-apply`, `job-contacts` | ежедневный дайджест вакансий из Telegram/RSS в папку Mail.ru, отклики на сайтах самих работодателей с резюме под вакансию и прямой выход на рекрутеров и тимлидов по открытым источникам |
| `tg-bridge` | `tg-bridge` | Telegram-бот как канал «человек в цикле»: агент спрашивает с кнопками и ждёт ответа (подтверждение отправки, SMS-код), шлёт уведомления и файлы, читает пересланное тобой, кнопки запускают разрешённые локальные команды |

Просто скажи агенту «скачай методичку по ИАД», «что нового по вакансиям» или «откликнись на эту стажировку» — нужный скилл подхватится сам.

Формат — открытый стандарт [Agent Skills](https://agentskills.io) (`SKILL.md`), работает в Claude Code, OpenCode и других агентах.

## Установка

**Claude Code (через marketplace):**
```
/plugin marketplace add Sapar-hub/sapar-skills
/plugin install mirea-moodle@sapar-skills
/plugin install job-search@sapar-skills
/plugin install tg-bridge@sapar-skills
```

**Claude Code / OpenCode (вручную):**
```bash
git clone https://github.com/Sapar-hub/sapar-skills
# Claude Code: ~/.claude/skills/   OpenCode: ~/.config/opencode/skills/
cp -r sapar-skills/plugins/*/skills/* ~/.claude/skills/
```

Нужны: `bash`, `curl`, `python3`; для pdf — `libreoffice`. Для аудита SyncShare дополнительно Node.js, Chrome/Chromium, `openssl`, `unzip` и `xvfb-run` на headless-машине. Для `job-search` — Docker (RSSHub), systemd `--user`, Node.js и Chromium (Playwright), ящик Mail.ru с паролем для внешних приложений.

## MIREA Moodle

Логин и пароль передаются только через переменные окружения:
```bash
export KC_USER='<student>@edu.mirea.ru' KC_PASS='...'
```
Дальше агент сам запускает `scripts/mirea.sh` (`check` → `start` → `otp <код>` → `courses` → `course <id>` → `folder <id>` → `get <url>`). Скрипт можно запускать и руками, без агента.

## SyncShare audit

`syncshare-audit` (в плагине `mirea-moodle`, использует его `mirea.sh` для логина) воспроизводит read-only аудит покрытия тестов SyncShare:

1. инвентаризация тестов курса (окно, попытки, review);
2. сохранение страниц попыток/просмотра — новая попытка только с явного согласия, для тестов с одной попыткой есть блокировка;
3. прогон **настоящего** расширения в локальном моке: `questionIdentity` считает само расширение, текст вопросов никуда не отправляется;
4. один анонимный `GET /api/v2/quiz/solution` на вопрос (rate limit, только чтение);
5. отчёт: сколько вопросов есть в базе и почему часть тестов возвращает пусто.

Пошаговый сценарий — в `plugins/mirea-moodle/skills/syncshare-audit/SKILL.md`. Скрипт `scripts/setup.sh` скачивает расширение, ставит Playwright, находит Chrome и генерирует локальный сертификат. Состояние по умолчанию — `~/.syncshare-audit`.

`setup.sh` также применяет к распакованной копии расширения небольшой локальный fallback настроек (telemetry off), чтобы обойти гонку инициализации в 2.19.0. CRX, парсер вопросов и вычисление `questionIdentity` не меняются.

Жёсткие правила: только свой аккаунт и свой Moodle-хост, только `GET quiz/solution` в production, без отправки текста вопросов, без POST в `quiz/attempt`/`quiz/review` в production, без сдачи попыток.

## Job search

**job-digest** — `feeds.txt` (Telegram-каналы и RSS) → локальный RSSHub в Docker → фильтр по регуляркам из `keywords.txt` (уровень: стажёр/junior; направление: DS/ML/аналитика) → дедуп в sqlite → письмо-дайджест через IMAP APPEND в папку «Вакансии» → systemd-таймер раз в день. Заодно `mailsort.py` раскладывает входящие по папкам по `mail-rules.json` (только MOVE, ничего не удаляет).

```bash
plugins/job-search/skills/job-digest/scripts/install.sh   # RSSHub + конфиг в ~/.config/job-digest + таймер
export MAILRU_USER=... MAILRU_APPPASS=...                   # или ~/.config/job-digest/env (chmod 600)
```

**job-apply** — тонкий CLI над долгоживущим Chromium (`scripts/browser.mjs`: `goto`, `text`, `snap`, `fill`, `upload`, `click`, …): агент читает форму текстом и заполняет её из `~/.config/job-apply/profile.yaml`. Резюме собирается под каждую вакансию из одного мастер-файла (`resume.mjs check` ловит факты, которых нет в мастере; `render` → PDF).

Перед резюме — preflight: `browser.mjs live <url>` (вакансия ещё открыта? HTTP, «вакансия закрыта», редирект на список, кнопка отклика) и `precheck.mjs` (свой чёрный список компаний/команд/доменов + дубли и репосты по прошлым откликам). Обе проверки только предупреждают, решает пользователь.

`hh.mjs sync <трек> <tailored.yaml>` переписывает резюме трека на hh.ru («Обо мне», ключевые навыки, ЗП пустая) из того же tailored-файла, что и PDF, — второй канал отклика без ручного копипаста.

Правила скилла: отклик на сайте работодателя и, если вакансия есть там же, на hh.ru (без прочих агрегаторов и посредников), никаких выдуманных навыков, зарплату не указывать, финальная отправка — только после явного «да» от пользователя. Профиль и резюме лежат вне репозитория.

**job-contacts** — OSINT-sourcing в обратную сторону: вместо ATS-стены найти рекрутера и тимлида нужной команды по открытым источникам (текст вакансии, карьерные страницы, Habr и Habr Career, доклады на конференциях, GitHub-организации, публичные TG-каналы), собрать карту найма «компания → команда → люди» и написать один раз по делу.
- `contacts.py extract <url|file>` — email, `@handle`, `t.me/…` и рабочие телефоны рядом с HR-словами, с контекстом;
- `contacts.py add … --source <URL>` — каждый контакт хранится с URL, где он опубликован; без источника не сохраняется;
- `contacts.py map`, `due`, `log` — карта найма, кому пора написать или напомнить, журнал касаний;
- `send.py` — письмо через SMTP Mail.ru с копией в «Отправленные»; без `--yes` только черновик. Telegram не автоматизируется: скилл выдаёт ссылку и текст.

**Telegram (опционально, с плагином tg-bridge).** Всё работает и без него; с ним:
- дайджест: каждый подходящий пост приходит в бота с кнопками «N» (в очередь откликов), «Скип», «В blacklist» (на разбор в чёрный список); письмо в «Вакансии» остаётся архивом;
- автоотклик: «N» → `queue.tsv` → `job-apply-worker` (`scripts/install-worker.sh`) запускает `claude -p` по одной вакансии: сайт работодателя, preflight, резюме, форма — а все вопросы, капча (ссылка на `relay.mjs`), SMS-код и финальное «отправить» со скрином и PDF приходят в Telegram; нет ответа — элемент `paused`, ничего не отправлено; ход прогона виден в одном сообщении, которое обновляется на месте и в конце становится итогом (при ошибке приходит лог файлом); headless-прогон не видит Google Sheets, поэтому строку трекера кладёт в `tracker.py` outbox, а хук напоминает перенести её в следующей интерактивной сессии (правила — `job-apply/references/auto-apply.md`);
- job-contacts: подтверждение письма кнопкой, TG-outreach в один тап (текст копируется, кнопка «отправил» пишет журнал), ежедневный follow-up после дайджеста, пересланный ответ рекрутера → журнал и трекер.

Границы зашиты в скрипты: только контакты, которые человек сам опубликовал как рабочие (никаких «пробивов», утечек и личных телефонов, 152-ФЗ); 1 сообщение + 1 напоминание через ≥7 дней; ≤10 писем в день; не больше двух людей из команды.

## tg-bridge

```bash
plugins/tg-bridge/scripts/install.sh     # токен от @BotFather в ~/.config/tg-bridge/env (TG_TOKEN=…, TG_PROXY=… если надо)
# потом /start боту в личке — демон привяжет этот чат, остальные чаты игнорируются
tg ask "Отправить отклик?" --photo shot.png --buttons "отправить,правка,стоп"   # stdout = ответ, exit 2 = таймаут
tg send "готово" --doc resume.pdf
tg inbox                                  # что ты переслал боту (JSON, помечено untrusted)
```
**Задачи из чата.** Если есть `~/.config/tg-bridge/agent.json`, твой обычный текст боту становится задачей. Пересланное и файлы при этом остаются данными, а через 15 с без твоего текста агент сам продолжит сессию с ними. Например: перешли ответ рекрутера и напиши «разбери и запиши в трекер». `scripts/agent.py` запускает `claude -p` со скиллами. Ход задачи виден в одном сообщении, которое в конце становится ответом. Одна вкладка (топик, Threaded Mode) — одна задача со своей сессией: задача в общем чате открывает новую вкладку, сообщение внутри вкладки продолжает её; каждый автоотклик тоже в своей вкладке. Команды: `/status`, `/stop`, `/inbox`. job_tracker без коннекторов пишется через Apps Script web app (`job-apply/apps-script/tracker.gs` + `scripts/sheet.py`).

Один демон (`systemd --user` `tg-bridge`) держит `getUpdates`; кнопки `--button "label=action:arg"` запускают только команды из `tg action add` (argv без shell). Хук `UserPromptSubmit` сообщает агенту, что в inbox что-то есть, но содержимое в контекст сам не подкладывает.

## Безопасность

- Пароль нигде не сохраняется. Куки лежат локально в `~/.mirea` (`MIREA_DIR`).
- Пароль Mail.ru — только из переменных окружения или `~/.config/job-digest/env`, в репозиторий не попадает.
- Токен бота — в `~/.config/tg-bridge/env` (chmod 600). Переписка с ботом идёт через серверы Telegram (не E2E): пароли и токены туда не шлются.
- 2FA **не обходится**: код каждый раз вводишь ты сам.
- `otp-email` (черновик, по умолчанию выключен) читает код из ящика Mail.ru по app-password и **удаляет письмо с кодом**; чтобы не удалял — `MIREA_KEEP_OTP=1`.

## Дисклеймер

Неофициальные инструменты, с РТУ МИРЭА, SyncShare и работодателями не связаны. Работает только с твоим собственным аккаунтом и делает то же, что ты делаешь в браузере. Если вёрстка SSO/Moodle поменяется, что-то может сломаться — issues и PR приветствуются.
